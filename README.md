# nurcahyaari-lab-manifests

This is everything that runs inside my homelab kubernetes cluster. The cluster itself, I mean the VMs, kubeadm, calico, that's in [nurcahyaari-lab-infra](../nurcahyaari-lab-infra/readme.md). This repo is what goes on top of it.

I use [Flux](https://fluxcd.io) here. Flux runs inside the cluster, watches the `main` branch of this repo, and applies whatever is in it. So I don't `kubectl apply` anything by hand anymore. I push to git, Flux does the rest.

Basically git is the source of truth. If it's not in git, it shouldn't be in the cluster.

## The folders

```
clusters/homelab/          the first thing Flux reads
  flux-system/             Flux itself, generated by flux bootstrap. Don't edit
  infrastructure.yaml      tells Flux to apply ./infra
  infra-config.yaml        tells Flux to apply ./infra/config
  apps.yaml                tells Flux to apply ./apps
infra/                     cluster level stuff
  kubelet-csr-approver/    approves the kubelet certificates
  metrics-server/          so `kubectl top` works
  external-secrets/        pulls secrets from Infisical
  config/                  config for the stuff above
    infisial-credentials/  Infisical login + the ClusterSecretStore
apps/                      the actual apps
  podinfo/                 demo app, I use it for testing
```

## How Flux applies it

There are 3 Flux Kustomizations, and they run in this order:

| name | folder | waits for |
| --- | --- | --- |
| `infrastructure` | `infra/` | nothing |
| `infrastructure-configs` | `infra/config/` | `infrastructure` |
| `apps` | `apps/` | both of them |

So why is `infra/config` separated from `infra`? Because a `ClusterSecretStore` needs the external-secrets CRDs to exist first. If I apply them together, the first apply fails, kubernetes doesn't know what a `ClusterSecretStore` is yet. That's also why `config` isn't listed in `infra/kustomization.yaml`.

Flux checks git every 1 minute, and re-applies everything every 10 minutes. All of them use `prune: true`. That means if I delete something from git, it gets deleted from the cluster too.

## Secrets

Secrets come into the cluster in 2 ways:

1. **sops.** The secret is encrypted and committed to git. Flux decrypts it using the age key in the cluster (secret `sops-age` in `flux-system`). Only files named `*.sops.yaml` get encrypted, see `.sops.yaml`. Right now I only use this for the Infisical login.
2. **external-secrets + Infisical.** The real secret lives in Infisical, project `nurcahyaari-lab`, env `prod`. I commit an `ExternalSecret` that says "I want this key", and external-secrets creates a normal kubernetes Secret from it.

App secrets go to Infisical. sops is only there so external-secrets can log in to Infisical, otherwise it's chicken and egg.

### Encrypting a file with sops

First you need the age private key on your laptop. On mac sops looks for it in `~/Library/Application Support/sops/age/keys.txt`. Or just point to it:

```sh
export SOPS_AGE_KEY_FILE=~/path/to/age.key
```

Then:

```sh
sops -e -i infra/config/something/my-secret.sops.yaml   # encrypt in place
sops infra/config/something/my-secret.sops.yaml         # open it decrypted and edit
```

Only `data` and `stringData` get encrypted. So the name and namespace are still readable in git.

### Using an Infisical secret in an app

1. Add the secret in Infisical (project `nurcahyaari-lab`, env `prod`)
2. Add an `ExternalSecret` next to the app:

   ```yaml
   apiVersion: external-secrets.io/v1
   kind: ExternalSecret
   metadata:
     name: my-app-secret
     namespace: my-app
   spec:
     refreshInterval: 1h
     secretStoreRef:
       kind: ClusterSecretStore
       name: infisical
     target:
       name: my-app-secret      # the kubernetes Secret it creates
     data:
       - secretKey: DB_PASSWORD # key in the kubernetes Secret
         remoteRef:
           key: DB_PASSWORD     # key in Infisical
   ```

3. **Add the namespace to the store.** The `infisical` store only allows the namespaces listed under `conditions` in `infra/config/infisial-credentials/cluster-secret-store.yaml`. Right now it's only `podinfo`. If I forget this, the ExternalSecret just doesn't sync.

## Adding a new app

1. create `apps/<name>/` with the yamls (namespace, deployment, service, etc)
2. add a `kustomization.yaml` in that folder that lists them
3. add `<name>` to `apps/kustomization.yaml`
4. commit and push

If not sure, just copy `apps/podinfo`.

Infra is the same, but under `infra/` and listed in `infra/kustomization.yaml`. If it needs CRDs from something in `infra/`, put it in `infra/config/` instead.

## Checking it

```sh
flux get kustomizations                                  # all should be Ready True
flux reconcile kustomization flux-system --with-source   # apply now, don't wait
flux logs --level=error                                  # when something isn't Ready

kubectl get clustersecretstore                           # infisical should be Ready
kubectl get externalsecret -A                            # should be SecretSynced
```

## Setup from zero

I only need this when the cluster is new or rebuilt.

1. Put the age key in the cluster first. Without it Flux can't decrypt anything:

   ```sh
   kubectl create namespace flux-system
   kubectl create secret generic sops-age -n flux-system \
     --from-file=age.agekey=$SOPS_AGE_KEY_FILE
   ```

   The file name must end with `.agekey`, that's how Flux knows it's an age key.

2. Bootstrap Flux to this repo:

   ```sh
   flux bootstrap github \
     --owner=nurcahyaari-lab \
     --repository=nurcahyaari-lab-manifests \
     --branch=main \
     --path=clusters/homelab
   ```

Done. Flux picks up the rest by itself, give it a few minutes.

## When something breaks

- **ClusterSecretStore says `unable to validate store`**: this message doesn't tell anything. The real error is in the controller logs:

  ```sh
  kubectl logs -n external-secrets deploy/external-secrets | grep -i error
  ```

  If it's a 404 like `Project with slug '...' not found`, the project slug in the store is wrong, or the machine identity isn't added to the project in Infisical yet.
- **Kustomization stuck at `dependency not ready`**: the one before it is broken. Fix that one first, check `flux get kustomizations`.
- **`failed to decrypt`**: `sops-age` is missing in `flux-system`, or the file was encrypted with another age key.
- **`kubectl top` not working**: check metrics-server is running, and the kubelet CSRs are approved (`kubectl get csr`).

## Watch out

- **Never commit a plain secret.** Name it `*.sops.yaml` and run `sops -e -i` before `git add`. Once it's pushed it stays in git history, even if I delete it later.
- **Delete from git = delete from cluster** (`prune: true`). Moving an app to another folder is fine. Deleting it by accident is not.
- **Don't edit `clusters/homelab/flux-system/`**. Flux generates it, the next bootstrap overwrites it.
- Yes, the folder is `infisial-credentials`, missing a `c`. It works, just be careful when typing the path.
